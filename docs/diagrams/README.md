# Architecture diagrams

The main diagram is embedded in [ARCHITECTURE.md](../ARCHITECTURE.md).

| File | Purpose |
| --- | --- |
| `component-architecture.png` | 3200 × 2040 image for documentation and high-density displays. |
| `component-architecture.svg` | Vector export with embedded icon assets. |
| `component-architecture.drawio` | Editable diagrams.net document: shapes, text, icons, and orthogonal connectors. |
| `icons/` | Cached browser and component icon images included in the diagram. |

## Edit in a diagram app

Open `component-architecture.drawio` in [diagrams.net](https://app.diagrams.net/) using **File → Open from → Device**. The XML is uncompressed and all elements remain editable. Icon images are embedded, so opening the file does not require access to this repository or the installed browser applications.

The PNG and SVG exports in this repository are generated by the renderer below. If you edit the `.drawio` file directly, export updated PNG/SVG files from diagrams.net and commit them together; running the renderer again will restore its defined layout.

## Diagram conventions

- Dashed enclosures show the local device and process boundaries.
- Rectangular components represent executable services or UI components.
- The database cylinder represents the usage repository backed by local SwiftData persistence.
- Solid connectors show state and usage-data flow. Dashed connectors show live status and user-control flow.
- The architecture is proposed. Browser IPC, permissions, and support still require Task 1 validation in the [implementation tracker](../IMPLEMENTATION.md).

## Regenerate

From the repository root on macOS with the Swift toolchain installed:

```sh
swift -module-cache-path /private/tmp/surfmeter-swift-cache scripts/render-architecture.swift
```

The renderer uses AppKit, CoreGraphics, and CoreText with no third-party dependencies. It generates the PNG at 2× resolution, a vector SVG with embedded icons, and a matching diagrams.net document. Layout is defined in `scripts/render-architecture.swift`.

Review the generated image for clipped labels, connector overlaps, icon visibility, and readability before committing.

## Icon sources

- **Safari:** Apple, extracted from the installed Safari application icon.
- **Google Chrome:** Google, extracted from the installed Chrome application icon.
- **Component, CPU, connector, monitor, window, and settings symbols:** Apple's [SF Symbols](https://developer.apple.com/sf-symbols/), rendered in a consistent neutral color.

The exported PNG icons are cached in `icons/`. Normal regeneration uses those committed assets and does not require Safari or Chrome to be installed. Rebuilding a missing browser icon requires the corresponding app in `/Applications`; rebuilding a missing component icon uses the macOS system symbol library. Browser names and marks remain those of their respective owners.
